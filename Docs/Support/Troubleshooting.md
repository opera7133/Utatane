# 困ったとき

まず、同梱ゴースト「りあ」でも同じ問題が起きるか確認すると、本体全体の問題か、特定のコンテンツの問題かを切り分けやすくなります。

## アプリを開けない

未署名の配布版でmacOSが止めている場合は、[初回起動の説明](../Guide/Getting-Started.md)を確認してください。対応環境はmacOS 14以降です。別の場所から入手した同名アプリと取り違えていないかも確認します。

## キャラクターが表示されない

1. メニューバーの「操作」→「Surfaceを再表示」を試します。
2. 表示できる場合は「機能」→「復旧操作」→「ウインドウ位置を初期化」を試します。
3. 「ゴーストを変更…」で別のゴーストを選びます。
4. エクスプローラと「設定」→「コンテンツ」で、対象フォルダと有効・無効を確認します。読み込み先を変更した場合は再起動します。

ゴーストが未インストールの状態ならNARを追加します。特定のシェルだけで起きる場合は、別のシェルと通常表示でも試してください。

## 表示されるが会話しない・反応しない

ダブルクリックなど、ゴーストが対応する操作をREADMEで確認します。自動会話がない場合は「設定」→「ゴースト」の会話間隔と、ゴースト自身の会話設定を確認します。

特定のゴーストだけで起きるなら、[ゴースト動作確認情報](Compatibility.md)と[SHIORI・SAORIの対応範囲](Native-SHIORI.md)を見てください。同じSHIORI名でも、使うモジュールや命令によって結果が異なります。

## 文字やキャラクターが小さい・大きい

キャラクターとバルーン全体の倍率は「ゴースト」、文字倍率は「喋り / バルーン」です。バルーン個別倍率が選べない場合は「バルーンをシェル倍率に連動」を確認します。

## ネットワーク更新が失敗する

ネット接続、配布元のURL、配布サイトが現在も公開されているかを確認します。配布元に更新定義がないコンテンツは本体から更新できません。本体の更新、コンテンツの更新、RSS巡回は別の処理です。

HTTPSの証明書エラーを回避するために検証を無効化する設定はありません。配布元側の問題か、Macの日時や接続環境の問題かを確認してください。

## 読み上げ・音声認識が動かない

「設定」→「音声」の有効化を確認します。マイクと音声認識の許可はmacOSの「プライバシーとセキュリティ」で確認できます。外部の音声エンジンには、起動、実行ファイルの指定、URL、APIキーなどが必要なものがあります。[音声の設定](../Guide/Speech.md)を参照してください。

## 診断と報告

右クリックの「情報」→「開発用パレットを表示」、または本体設定の「詳細」からログを確認できます。再読み込みは「機能」→「復旧操作」→「現在のゴーストを再読み込み」です。

SHIORIが起動しない場合は、「情報」→「SHIORI読み込み診断…」、またはメニューバーの「操作」から診断を開きます。対象ゴーストを選ぶと、SHIORI指定と`shiori.macos`、モジュールの場所、CPU、公開シンボル、依存ライブラリを確認できます。「再診断」で情報を更新し、「コピー」でレポートを取得できます。

この診断はモジュールを追加で読み込まず、ファイルを静的に調べます。「Last load / initialization」は、このアプリ起動中に実際に試したエンジンの初期化結果です。まだ起動していないゴーストには結果がありません。シンボルが揃っていても、会話やイベント処理が正常に動くことまでは保証しません。

解決しない場合は[GitHub Issues](https://github.com/opera7133/Utatane/issues/new/choose)へ、次の情報を添えて報告してください。

- Utataneのバージョン、macOSのバージョン、Apple SiliconかIntelか。
- ゴースト・シェル・バルーンの名前と入手元。
- 起きたこと、期待した動き、再現する操作。
- 同梱ゴーストでも起きるか、通常表示・ウィンドウモードのどちらか。
- 必要な範囲のログやスクリーンショット。

APIキー、個人情報、再配布が許可されていない辞書・コンテンツ本体は添付しないでください。
